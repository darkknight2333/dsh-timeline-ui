## 自动化（`npm run verify`）

46 项，全部通过。测试直接加载 **构建后的** `lib/client.js`，用伪 DOM / 伪 React 跑真实代码路径：

| 组 | 覆盖 |
|---|---|
| module | 模块 id 等于包名、`inject`/`apply` 形状、六个槽位注册（列表、面板、图标、两个设置行）、只注入公开服务、基础样式注入 |
| grouping | 今天/昨天按日历日、跨零点（23:55 vs 00:05）、跨年（12-31 vs 01-01）、同年「月日」、往年带年份、DST 前后 23h/25h 仍算一天 |
| list | 15 条上限、归档过滤（`session-` 前缀容错）、编号 1..15、Ctrl 提示只在前 9 条 |
| rail adapter | 结构探测命中、伪造的干扰 `<nav>` 不命中、样式表用发现的类名前缀、不含写死哈希、左置规则、`--dtu-rail-w` 变量、鱼眼峰值与对称衰减、离开后清空 |
| switches | 两个开关默认开、关掉后反注册 / 移除样式 |
| teardown | 无残留的 document 指针监听、window 监听、MutationObserver、样式表 |
| portability | 产物无绝对路径、无 `link:`、无 profile 名、无写死 CSS 哈希 |

```bash
npm run verify
```

## 人工界面确认（发布前需要你在真机上过一遍）

勾选后才能把对应版本写成“已验证”：

- [ ] 安装后侧边栏变为日期分组列表，编号连续
- [ ] 关闭「对话列表按日期分组」→ 立即恢复原生列表；再打开 → 恢复分组
- [ ] 导航条在对话区左边缘，默认等长短线
- [ ] 鼠标进入 → 单峰、上短下短；上下移动 → 波峰连续跟随；离开 → 180ms 内回到等长
- [ ] 点击横线跳转到对应轮次；悬停显示该轮预览
- [ ] 拖动窗口宽度：<900px 时导航条自动隐藏（原生行为），拉宽后回来
- [ ] 折叠/展开左侧边栏：导航条位置跟随，不遮挡正文
- [ ] 明暗主题各看一遍：横线、编号、选中高亮、开关都正常
- [ ] 超长会话（≥30 轮）：导航条内部可滚动，鱼眼仍正常
- [ ] 关闭「导航条」开关 → 回到右侧原样；再打开 → 回到左侧
- [ ] 卸载插件 → 完全恢复原生界面，会话与归档状态不受影响

## 回归方法

导航条探测依赖 Harness 内部结构。新版发布后如果导航条失效：

1. 看设置行是否出现「未在当前 DSH 版本中找到对话导航条」；
2. 用浏览器控制台确认对话区是否还有 `<nav>` 里成组的 `button[data-index]`；
3. 结构变化则更新 `src/client.js` 里 `discoverRail()` 的判定并补一条测试。
